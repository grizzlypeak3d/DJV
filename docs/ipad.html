DJV Studio for the iPad is the same application as on the desktop: the same files, timelines, color management and comparison, drawn through Metal. This page covers what is different on a tablet: how files are reached, what a finger does in place of a mouse and keyboard, and what the hardware allows.

Opening files

iOS grants an application access to files one at a time, through the system's picker. File > Open shows the picker for a file: a movie, an image, an OpenTimelineIO timeline or bundle (.otioz), or a review. Files can be anywhere the Files app reaches: the iPad, iCloud Drive, a USB-C drive, or a network share added in Files.

A timeline, a review, or one frame of an image sequence refers to files beside it, which the picker's grant does not cover. Opening one asks for its folder, with the picker for folders: the grant then covers everything in the folder, the sequence is gathered from the frame, and the folder is remembered so it is not asked for again.

Recent files are kept as bookmarks, so they open again without the picker, and they survive an update of the application.

A bundle (.otioz) is the easiest way to carry a cut to the iPad: the timeline and its media in one file, sent by AirDrop, copied to a drive, or opened in place from a share.

Touch

A tap is a click. Dragging on the timeline scrubs; dragging in the viewer does what the current mouse tool does. The view tool bar holds the mouse tools — pan, compare wipe, color pick and frame shuttle — which stand in for the modifier keys a desktop uses with a mouse.

  • Two fingers pan, and a pinch zooms, in the viewer and in the timeline.
  • A swipe scrolls a list, with momentum.
  • A double tap on the viewer frames the picture in the view.
  • A finger held for half a second opens the context menu, as a right click does on the desktop. The press still counts: on the timeline the current frame stays where the finger rests, and in the file browser the pressed file stays selected, so the menu applies to it.
  • Splitters between the picture, the timeline and the tools have a grip, and take a finger from either side of the line.

A finger has no hover, so what hover does on the desktop has another route here. Tooltips appear only with a pointer (a trackpad or mouse connected to the iPad); every tool bar button is also a menu item with its name. The timeline's frame preview under the pointer is also a pointer feature: scrubbing shows the frame in the viewer instead. Menus opened by touch start with no item selected.

Text fields take the on-screen keyboard when tapped. A hardware keyboard works as on the desktop, with the same shortcuts.

Layout

The interface is drawn larger than on the desktop, at a display scale suited to a finger (Settings > Style). The default layout keeps the menu bar, the view tool bar, the tab bar, the picture, the timeline and the playback controls; the other tool bars and the status bar are off, and can be turned on from the Window menu. The tools column takes more of the width than on the desktop, so that its forms have room.

Playback

Hardware decoding is on by default: the iPad decodes H.264 and HEVC in hardware on every model, ProRes from the A15 and M1 chips on, and AV1 from the M3 and A17 Pro on. Decoded frames stay on the GPU rather than being copied to memory, which is what keeps 4K playing on the smaller chips. An older iPad opening an AV1 file says so over the picture; the audio still plays. Everything else is decoded in software on the iPad's cores, where a large file may play below its rate.

The memory cache is sized to an eighth of the iPad's memory by default, since iOS stops an application that takes much more. When playback starts, and after a seek while playing, the clock waits for a second of video to be cached, so the picture moves when it does. Once running the clock is not held again: a file the iPad cannot decode in time plays at the rate it can, and the frames it could not show are counted as dropped (see Playback).

Dolby audio (AC-3, E-AC-3) is not built in, so a movie with such a track plays its picture without sound. On the desktop an external FFmpeg can fill that gap; on the iPad there is none.

External display

Window > Secondary puts the picture on a second screen — a television or monitor on a USB-C or Lightning adapter, or an AirPlay receiver — while the controls stay on the iPad. The secondary window covers the whole of that screen, and closes by itself when the screen goes away. AirPlay delays the audio by the route's own latency, which the player takes into account.

Not on the iPad

Blackmagic output, Python scripting and the command line are desktop features. The application is not quit from a menu, as on the desktop; iOS suspends and ends it as it does any application.

The documentation and the licenses open inside the application, from the Help menu.

The log is in the Logs folder of the application's files, which the Files app shows under On My iPad. The log of the run before is kept beside it, ending in .prev.log: after a crash or a freeze, that is the one to send with a report.
